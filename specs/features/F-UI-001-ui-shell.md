## 1. Назначение

Каркас приложения: layout, навигация, маршруты, дизайн-система и базовые компоненты, Dashboard и страницы модулей с честными состояниями «ещё не реализовано», страница 404, сообщение о недоступности сервера и БД. На этом каркасе строятся все следующие модули.

## 2. Scope

**В рамках:**
- Layout для широкого экрана (боковая навигация) и узкого экрана (мобильная панель + выдвижное меню).
- 6 разделов навигации и маршруты к ним, страница 404.
- Дизайн-токены (цвета, типографика, отступы, радиусы) и базовые компоненты.
- Dashboard без реальных данных — карточки разделов в состоянии «ещё не реализовано».
- Страницы-заглушки модулей с указанием этапа реализации.
- Баннер ошибки при недоступности сервера или БД (проверка состояния — единственный реальный запрос к backend на этом этапе).
- Обработка неожиданной ошибки отрисовки страницы (error boundary).
- Dev-витрина компонентов (только в режиме разработки).

**Вне рамок:**
- Бизнес-логика любых модулей, CRUD, формы ввода данных.
- Реальные данные и графики на Dashboard (Этап 5).
- Быстрый ввод (Voice Inbox, Этап 3).
- Аутентификация, настройки, профиль.
- Светлая тема, i18n, PWA/офлайн.

## 3. Пользовательские сценарии

- **US-1.** На компьютере я вижу все разделы в боковой навигации и перехожу в любой одним кликом.
- **US-2.** На телефоне я открываю выдвижное меню одной кнопкой, выбираю раздел, меню закрывается.
- **US-3.** Я открываю ссылку на раздел напрямую или обновляю страницу — попадаю туда же.
- **US-4.** Я открываю раздел, который ещё не готов, и сразу понимаю это и когда он появится.
- **US-5.** Если сервер или база данных недоступны, я вижу это над содержимым страницы и могу повторить проверку.
- **US-6.** Я открыл устаревшую закладку или ошибся в адресе — вижу страницу «Страница не найдена» и одним нажатием возвращаюсь на главную.
- **US-7.** Я пользуюсь приложением только с клавиатуры.

## 4. Бизнес-правила

- **BR-1.** UI не показывает фиктивных данных: ни чисел, ни графиков, ни «нулевых» значений там, где данных ещё нет. Нереализованный раздел обозначается текстом «В разработке» с номером этапа.
- **BR-2.** На странице нет элементов управления, которые ничего не делают. Нереализованная функция не отображается как неактивная кнопка — вместо неё текстовое состояние. Исключение — dev-витрина `/dev/ui` (только режим разработки, AC-UI-010): она показывает компоненты во всех состояниях, в том числе disabled.
- **BR-3.** Отказ backend не блокирует навигацию по каркасу.
- **BR-4.** Граница layout: ширина окна **≥ 1024 px** (широкий экран) — боковая навигация; **< 1024 px** (узкий экран) — мобильная панель и выдвижное меню.

## 5. Критерии приёмки

Критерии сгруппированы по условию применения. Критерий из группы 5.1 описывает только широкий экран, из 5.2 — только узкий; всё, что касается перехода между ними, — в 5.3. ID постоянные: при перегруппировке номера не меняются, новые критерии получают следующий свободный номер, удалённые номера не используются повторно. Выведены из употребления: AC-UI-019, AC-UI-020, TC-UI-039 (v0.3, решение D-3 изменено).

### 5.1 Широкий экран (ширина ≥ 1024 px)

| ID | Критерий |
|---|---|
| **AC-UI-001** | Слева постоянно видна боковая навигация, справа — рабочая область (`main`). |
| **AC-UI-022** | Каждый интерактивный элемент имеет область нажатия не меньше 24×24 CSS px (область нажатия может быть больше видимого элемента). |

### 5.2 Узкий экран (ширина < 1024 px)

Узкий экран — это телефон, планшет или суженное окно браузера на компьютере, поэтому требования к клавиатуре (Esc, Tab) здесь тоже действуют.

| ID | Критерий |
|---|---|
| **AC-UI-002** | Сверху мобильная панель с названием приложения и кнопкой «Открыть меню». Нажатие на кнопку открывает выдвижное меню с основной навигацией. |
| **AC-UI-015** | Выдвижное меню закрывается каждым из способов: выбором раздела, кнопкой «Закрыть меню», клавишей Esc, нажатием на затемнённый фон. После закрытия фокус возвращается на кнопку «Открыть меню». |
| **AC-UI-016** | Пока выдвижное меню открыто, фокус клавиатуры не выходит за его пределы, а страница под ним не прокручивается. |
| **AC-UI-024** | Если выдвижное меню открыто, кнопка «Назад» браузера или системный жест «Назад» телефона закрывает выдвижное меню; раздел и адрес страницы не меняются, фокус — на кнопке «Открыть меню». Выдвижное меню не считается шагом истории: после его закрытия любым способом одно нажатие «Назад» открывает предыдущий раздел, а «Вперёд» никогда не открывает выдвижное меню. |
| **AC-UI-023** | Каждый интерактивный элемент имеет область нажатия не меньше 44×44 CSS px (область нажатия может быть больше видимого элемента; иконка может быть меньше). |

### 5.3 Переключение между широким и узким экраном (граница BR-4)

| ID | Критерий |
|---|---|
| **AC-UI-017** | В любой момент на странице ровно одна форма основной навигации: при ширине ≥ 1024 px — боковая навигация (мобильной панели, кнопки «Открыть меню» и выдвижного меню нет); при < 1024 px — мобильная панель (боковой навигации нет). При изменении ширины окна форма меняется без перезагрузки страницы. |
| **AC-UI-018** | Если выдвижное меню открыто и ширина окна становится ≥ 1024 px, выдвижное меню закрывается, прокрутка страницы разблокирована. Если фокус был внутри выдвижного меню, он переходит на активный пункт боковой навигации. |

### 5.4 Общие для обеих версий

| ID | Критерий |
|---|---|
| **AC-UI-003** | Основная навигация содержит ровно 6 разделов, расположенных сверху вниз строго в таком порядке: 1 — «Обзор», 2 — «Питание», 3 — «Голосовой ввод», 4 — «Задачи», 5 — «Заметки», 6 — «Привычки и вес». Переход между разделами без полной перезагрузки страницы. |
| **AC-UI-004** | Пользователь остаётся в том же разделе после обновления страницы, при открытии закладки и при открытии ссылки на раздел в новой вкладке — то есть каждый маршрут из карты открывается по своему адресу. | **AC-UI-005** | Любой неизвестный путь (включая вложенный, например `/nutrition/abc`) показывает страницу 404: заголовок «Страница не найдена», пояснение «Такой страницы нет. | **AC-UI-006** | Страница нереализованного раздела показывает: заголовок раздела (`h1`), описание назначения и статус «В разработке · Этап N» — тексты и этапы по таблице §7.5. В рабочей области нет кнопок (кроме «Повторить» в баннере ошибки, AC-UI-021), полей ввода, чисел-показателей (метрик, счётчиков, процентов) и графиков; номер этапа в статусе показателем не считается. |
| **AC-UI-007** | Dashboard показывает заголовок «Обзор», текущую дату по локальному времени устройства в формате «вторник, 27 октября», и 5 карточек в порядке: «Задачи и события», «Привычки», «Вес», «Калории за день», «Быстрый ввод». Каждая карточка — в состоянии «В разработке · Этап 5» (этап, когда карточка начнёт показывать данные, решение D-12) со ссылкой «Перейти в раздел»; иконки, описания, этапы и адреса ссылок — по таблице §7.4. На Dashboard нет чисел-показателей, графиков и полей ввода. Дата вычисляется при открытии Dashboard и обновляется в 00:00 по локальному времени устройства, если страница открыта (решение D-6). |
| **AC-UI-008** | Приложение проверяет состояние системы запросом `GET /api/v1/system/health`: при загрузке; когда вкладка снова становится видимой после того, как была скрыта; через 60 с после завершения предыдущей проверки любого вида (при загрузке, при возврате на вкладку, по «Повторить»), пока вкладка видима; по кнопке «Повторить» (AC-UI-021). Пока вкладка скрыта, запросы не отправляются; одновременно выполняется не больше одного запроса. Результат проверки: «Система работает» — 200 и `status: UP`; «База данных недоступна» — 503 и `status: DOWN`; «Сервер недоступен» — сетевая ошибка, нет ответа за 5 с или любой другой ответ. Отдельного постоянного индикатора нет: при «Система работает» о состоянии системы ничего не показывается, ошибки показывает баннер (AC-UI-021). Навигация работает при любом результате. |
| **AC-UI-021** | Если последняя проверка состояния (AC-UI-008) вернула «База данных недоступна» или «Сервер недоступен», первым элементом рабочей области (перед `h1`) показывается баннер ошибки с этим текстом и кнопкой «Повторить» (вид — §7.7). Баннер сдвигает содержимое вниз и ничего не перекрывает, его появление не перемещает фокус, он объявляется скринридером (`role="status"`). Пока выполняется любая проверка состояния (AC-UI-008 — периодическая, при возврате на вкладку или по «Повторить»), кнопка «Повторить» в состоянии loading, нажатие на неё не отправляет запрос, баннер остаётся на месте. Когда очередная проверка возвращает «Система работает», баннер исчезает; если фокус был на кнопке «Повторить», он переходит на `h1` рабочей области. |
| **AC-UI-009** | Цвета, шрифты, отступы и радиусы заданы токенами в одном месте (CSS-переменные + тема Tailwind); в компонентах нет «зашитых» цветов. Есть базовые компоненты: `Button` (варианты primary / secondary / ghost / destructive; состояния default, hover, focus-visible, disabled, loading), `Card`, `PageHeader`, `EmptyState`, `StatusBadge`, `Spinner`, `ConfirmDialog`, `Toast`. `Button` в состояниях disabled и loading не реагирует на нажатие; loading показывает индикатор и имеет `aria-busy="true"`. `ConfirmDialog` вызывает действие только после явного подтверждения. `Toast` объявляется скринридером (`aria-live`) и закрывается вручную или автоматически через 5 с. |
| **AC-UI-010** | В режиме разработки страница `/dev/ui` показывает все базовые компоненты во всех вариантах и состояниях. В production-сборке `/dev/ui` показывает страницу 404, как любой неизвестный путь (AC-UI-005; HTTP-статус не проверяется), и код витрины не попадает в бандл. E2E-тесты production-сборки запускаются против `pnpm preview` (`vite preview`). |
| **AC-UI-011** | Доступность: ориентиры — на широком экране `nav` (с подписью «Основная навигация») и `main`; на узком при закрытом выдвижном меню `header` и `main`; при открытом — `header`, `nav` и `main`; ровно один `h1` на странице; первая по Tab ссылка — «Перейти к содержимому»; все интерактивные элементы доступны с клавиатуры, порядок перехода по Tab — по областям: сначала навигация (боковая навигация или мобильная панель) сверху вниз, затем рабочая область сверху вниз и слева направо; фокус виден; контраст текста ≥ 4.5:1, элементов интерфейса и фокуса ≥ 3:1; при `prefers-reduced-motion: reduce` анимации отключены; axe-core не находит нарушений уровня serious/critical ни на одном маршруте. |
| **AC-UI-012** | На всех маршрутах при ширине 320–1920 px нет горизонтальной прокрутки страницы, текст не обрезается и не перекрывается. При масштабе браузера 200 % (окно 1280×800 px) весь текст и все элементы управления доступны без горизонтальной прокрутки и не перекрываются. |
| **AC-UI-013** | Только тёмная тема (`color-scheme: dark`): графитовый фон и поверхности, один акцентный цвет. Акцент используется только для активного раздела, primary-кнопок, фокуса и ссылок. |
| **AC-UI-014** | Если при отрисовке страницы возникает непредвиденная ошибка, в рабочей области показывается состояние «Что-то пошло не так» с пояснением «Страницу не удалось показать.» и кнопкой «Перезагрузить страницу»; навигация работает, переход в другой раздел показывает его обычное содержимое, без состояния ошибки. Ошибка пишется в консоль. |
| **AC-UI-026** | Пока код раздела загружается (ленивая загрузка), рабочая область пуста; если загрузка длится дольше 300 мс, в ней показывается `Spinner`. Если код раздела не удалось загрузить, показывается состояние ошибки отрисовки (AC-UI-014). Навигация работает в обоих случаях. |
| **AC-UI-025** | Расположение, порядок и размеры элементов экранов соответствуют схемам и таблицам элементов §7 на широком (1440 px) и узком (390 px) экране; цвета — токены §9. Размер элемента — внешний, вместе с границей; совпадение точное, в целых CSS px. |

## 7. Экраны, элементы и UI-состояния

Схемы нормативны по расположению и порядку элементов; размеры и тексты в таблицах — тоже (AC-UI-025). Тексты на схемах — точные; сокращения с «...» (например, «Голосовой...») — только сокращение рисунка, в интерфейсе подпись показывается полностью. Цвета — токены §9; финальная визуальная проверка — TC-UI-034. На схемах `[i]` — место иконки (какая именно — таблица «Иконки», §4), `▌` — отметка активного раздела. Размеры — в CSS px.

`GET /api/v1/system/health` — Spring Boot Actuator, base path `/api/v1/system`, `show-details: never`. Статус отражает только приложение и БД: остальные health-индикаторы (например, свободное место на диске) на ответ не влияют.

| Ситуация | HTTP | Тело |
|---|---|---|
| Приложение и БД работают | 200 | `{"status":"UP"}` |
| БД недоступна | 503 | `{"status":"DOWN"}` |

В dev frontend обращается к backend через proxy Vite (`/api` → `http://localhost:8080`), CORS не нужен. Модель данных: нет.
