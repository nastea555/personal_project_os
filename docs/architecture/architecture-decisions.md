# Architecture Decision Records

Формат: контекст → решение → последствия. Статусы: Proposed / Accepted / Superseded.

---

## ADR-001. Модульный монолит

**Статус:** Proposed

**Контекст.** Один пользователь, шесть модулей, один разработчик-агент и один ревьюер. Микросервисы добавили бы сеть, деплой и согласованность данных без пользы.

**Решение.** Один frontend (SPA), один backend (Spring Boot), одна БД PostgreSQL. Внутри backend код делится по модулям-пакетам: `nutrition`, `recipes`, `voice`, `tasks`, `journal`, `habits`, `weight`, `common`. Модуль не обращается к таблицам другого модуля напрямую — только через его сервис.

**Последствия.** Простой запуск и отладка. Границы модулей держатся дисциплиной и code review, а не сетью; при необходимости проверяются ArchUnit-тестом.

## ADR-002. Frontend: React + TypeScript strict + Vite

**Статус:** Proposed

**Решение.** React, TypeScript (`strict: true`), Vite, Tailwind CSS, shadcn/ui (компоненты на Radix — доступность с клавиатуры из коробки), React Router, TanStack Query (серверное состояние), React Hook Form + Zod (формы), Recharts (графики).

**Последствия.** Серверное состояние живёт только в TanStack Query; глобальный стор (Redux и т.п.) не добавляем без обоснования.

## ADR-003. Backend: Java 21 + Spring Boot + Maven

**Статус:** Proposed

**Решение.** Java 21 LTS (есть в окружении: 21.0.12), Spring Boot, Spring Web, Spring Data JPA, Bean Validation, springdoc-openapi, Spring Boot Actuator (health). Сборка — Maven с Maven Wrapper (Maven 3.9.11 есть в окружении; Gradle отсутствует).

**Почему Maven, а не Gradle.** Уже установлен, декларативный `pom.xml` проще читать при изучении кода.

## ADR-004. Схема БД только через Flyway

**Статус:** Proposed

**Решение.** PostgreSQL 16. Все изменения схемы — миграции Flyway `V<n>__<описание>.sql`. `spring.jpa.hibernate.ddl-auto=validate` (Hibernate проверяет схему, но не меняет её). Применённые миграции не редактируются — только новые.

## ADR-005. REST API `/api/v1` + OpenAPI

**Статус:** Proposed

**Решение.** JSON REST, префикс `/api/v1`. Контракт описывается в `specs/api/` и публикуется через springdoc (`/swagger-ui`). Ошибки — единый формат RFC 9457 (Problem Details): `type`, `title`, `status`, `detail`, `errors[]` для полей валидации.

## ADR-006. AI-поставщик за интерфейсом, схема «предложить → подтвердить»

**Статус:** Proposed

**Решение.** Интерфейсы `SpeechToTextProvider` и `IntentParser` в backend. Реализация по умолчанию — без платного сервиса (распознавание речи браузером через Web Speech API, где поддерживается; разбор намерения — заменяемый поставщик, включая `none` → только ручной выбор категории). Ключи — только в переменных окружения. Ответ AI — черновик (`draft`), проходит детерминированную валидацию и не сохраняется без подтверждения пользователя.

**Последствия.** Voice Inbox работает в деградированном режиме (ручной ввод) при недоступном AI. Детали — в F-VOICE-001 (Этап 3).

## ADR-007. Калорийность приёма пищи — снимок на момент записи

**Статус:** Proposed

**Контекст.** Требование: редактирование рецепта не меняет историю дневника.

**Решение.** Запись дневника хранит рассчитанные значения (`kcal_total`, `kcal_per_100g`, `portion_grams`, название блюда) на момент записи, а ссылку на рецепт — только как справочную (nullable).

**Последствия.** Дублирование данных осознанное. Детали — в F-NUT-001 / F-REC-001 (Этап 2).

## ADR-009. Окружение разработки

**Статус:** Proposed — требует решения владельца

**Контекст (проверено 2026-10-27).** В облачной песочнице агента: Java 21.0.12, Maven 3.9.11, Node 22.23.4, npm 10.9.9, pnpm 10.28.0, Git 2.43, PostgreSQL 16.15 (локально, остановлен), Docker CLI 29.9 + Compose v5.6. Однако:

| Ресурс | Результат |
|---|---|
| Maven Central (`repo.maven.apache.org`) | 403, заблокировано прокси |
| `start.spring.io` | 403 |
| npm registry (`registry.npmjs.org`) | недоступен (DNS) |
| Docker daemon | не запущен |
| Docker Hub | 403 |

Без этих ресурсов нельзя установить ни одной зависимости из целевого стека, поэтому сборки и тесты в песочнице не выполнимы.

**Варианты.**
1. Разработка на машине владельца (Claude Code локально) — полный стек, Docker, Playwright.
2. GitHub-репозиторий: агент пишет код, проверки выполняет GitHub Actions; локально — только то, что не требует зависимостей.
3. Сменить стек под песочницу — **отклонено**: нарушает требования проекта.

**Решение:** ожидает выбора владельца.

**Ограничение владельца (2026-10-29), обязательно для варианта 1:** на диск C ничего нового не устанавливается. Всё, что нужно проекту, ставится только в `D:\Personal OS`:

| Что | Куда |
|---|---|
| Проект | `D:\Personal OS\personal-life-hub` |
| JDK 21, Maven, Node.js (portable/zip-версии) | `D:\Personal OS\tools\` |
| Кэш Maven (`maven.repo.local`) | `D:\Personal OS\cache\m2` |
| Кэш npm / pnpm store | `D:\Personal OS\cache\npm`, `D:\Personal OS\cache\pnpm` |
| Браузеры Playwright (`PLAYWRIGHT_BROWSERS_PATH`) | `D:\Personal OS\cache\ms-playwright` |
| Данные PostgreSQL | том Docker (образ диска Docker — `D:\Personal OS\docker`) |

Пути задаются переменными окружения в скрипте сессии проекта, системные PATH и переменные не меняются. Уже установленные программы (VS Code, существующий `C:\Users\user\.m2`) не трогаем и новые зависимости туда не пишем.

**Исключение (2026-10-29):** Docker Desktop разрешено установить на диск C (вместе с WSL 2). PostgreSQL для разработки запускается в контейнере через Docker Compose, отдельный portable PostgreSQL не нужен. Образы и тома Docker по возможности хранятся на D (Settings → Resources → Advanced → Disk image location → `D:\Personal OS\docker`).

## Соглашения

- Пакетный менеджер frontend: **pnpm** (есть в окружении, быстрый, строгий lock-файл). Альтернатива — npm.
- Даты дневника/привычек/веса — `LocalDate` (календарный день пользователя); события календаря — `OffsetDateTime` + часовой пояс пользователя (уточняется в Этапе 4).
- Единицы: кг (1 знак), г (целые), ккал (целые при отображении, хранение с точностью до 0.1).
